# Measurement and change workflow

1. **Define the outcome.** Choose one measurable business or user result. Document when it occurs, what deduplicates it, the denominator and how a record proves it happened. Qualify the difference between acquisition channel, event type and conversion status.
2. **Collect the baseline.** Keep equal complete windows in the source's reporting timezone. Use Search Console for eligible performance and coverage reports, GA4 for sessions and instrumented actions, and CRM or the relevant system for business outcomes. Record filters, attribution scope and freshness. When a deterministic join is missing, measure the stages separately. Export aggregates instead of personal data.
3. **Prioritize.** Tie each change to a supported mechanism, such as resolving an observed access failure or removing a dead end on the quote flow. Estimate expected direction and method of verification. Give numeric forecasts only when baseline and assumptions justify them.
4. **Apply within scope.** Work in the project's normal source or staging environment. Document URL set, owner, change, date, recovery path and intended exposure. Recheck rendering, analytics and outcomes affected by the change.
5. **Follow through.** Save before/after evidence for the same templates and query cohort. Record other changes and baseline coverage. Report counts, rates and time to maturity. Make clear where a result reflects only the sampled pages or model surface.

Source: [GA4 acquisition scopes](https://support.google.com/analytics/answer/11080067).
